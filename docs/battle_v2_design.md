# 《曙光冒險》戰鬥核心 v2 設計（依〈核心戰鬥與Build系統規格書 v1.0〉＋〈延伸規格〉）

玩家指示：「遊戲底層重製方案，所有戰鬥相關系統改動」；進行方式「一次全部重寫」；範圍「底層＋規格玩法＋多敵人」；規格缺頁「照你的邏輯補完」。
本文件是 v11 戰鬥重寫的依據。規格原文：docs/spec_core_v1_partial.txt、docs/spec_ext_partial.txt。現有機制清單：docs/battle_inventory_v10.7.md。

## A. 規格缺頁的補完（標註「補」）

**31. TriggeredEffect（補）**
- 條件成立後不得立即任意執行，而是建立 TriggeredEffect 放進觸發佇列。欄位：來源觸發器、擁有者、效果清單、priority、建立序號、父事件、觸發當下的快照、chain_depth。
- 目前事件的 POST 處理完後，依「系統強制 > 中斷／反應 > priority 高到低 > 來源行動順序 > 建立序號」排序執行。
- 執行前重新檢查：擁有者是否仍可作用（失去戰鬥能力者預設不觸發，資料可設 `whenDown`），使用次數是否仍有剩。
- 每個 TriggeredEffect 的效果都會產生新事件，parent 指向觸發它的事件。

**76–80（補）**
- 76 平衡紀錄：每次調整都寫入 docs/balance_log.md，包含修改前資料、修改內容、原因、預期影響，以及驗證結果（模擬報告前後比較）。
- 77 回歸基準：固定一組種子＋腳本戰鬥，記錄事件序列的雜湊值；底層修改後雜湊值改變必須說明原因。
- 78 除錯：開發模式可輸出整場戰鬥的事件鏈（id、parent、root、depth、phase、payload），觸發安全上限時自動輸出。
- 79 效能：單一行動事件數上限 512、事件鏈深度上限 8、反應深度上限 2、每行動觸發上限 32、每回合觸發上限 96，超過就中止該事件鏈並記錄。
- 80 存檔相容：資料 id 永久穩定，舊存檔讀取時做一次遷移（技能庫、技能槽），並記錄 `st.battleV = 2`。

## B. 架構（四層）

| 層 | 檔案 | 負責 |
|---|---|---|
| 資料層 | src/10b_bdata_*.js | 技能、狀態、資源、被動鍵、敵人、遭遇、職業、道具的定義（id、version、tags、enabled、metadata）。由既有內容表（MOVES、ORB_A、SIG、WSK、SPECIES、MON_PANEL、GEAR…）轉換，加上手寫的特殊機制資料。 |
| 規則層 | src/10c_brules.js | 傷害／治療公式、修正管線的順序、命中與會心、行動順序、狀態與資源規則、AI 評分、獎勵規則。 |
| 執行層 | src/10d_bcore.js | BattleCore：狀態機、ActionCommand、事件佇列（PRE／MAIN／POST）、觸發器、效果執行、可重現亂數、事件紀錄。完全不碰畫面。 |
| 顯示層 | src/10g_bscene.js | BattleScene：依事件紀錄播放動畫、訊息、數字、HP 條；收集玩家輸入並只提交 ActionCommand。 |

- 核心是同步執行的：推進到需要玩家輸入或戰鬥結束時停下，同時產生事件紀錄；顯示層照順序播放。所以核心可以在沒有畫面的情況下跑上千場模擬。
- 舊的 Battle 類別與所有 `Battle.prototype` 包覆程式碼在上線前全部移除，不保留第二套戰鬥流程。
- 英雄的基礎數值仍由 heroStats() 計算（屬性、裝備、詞綴、天賦都算進來），輸出的「被動鍵」交給資料層的被動鍵登錄表轉成修正器與觸發器，不在戰鬥流程裡寫 if。

## C. 戰鬥狀態機

`INIT → BATTLE_START → ROUND_START → COMMAND(WAITING_ACTION) → TURN_ORDER → ACTION_PREPARE → ACTION_EXECUTION → ACTION_END → (下一個行動 | ROUND_END) → VICTORY_CHECK → (ROUND_START | BATTLE_END)`

- 每個狀態都有合法的下一個狀態表，非法轉移在開發模式直接報錯；只有狀態機能改 `state`。
- COMMAND：回合開始時，玩家單位等待輸入、AI 單位立即決策，全部轉成 ActionCommand `{action_id, actor, type, skill, targets, meta}`。
- TURN_ORDER：依「行動優先度（逃跑 7 > 道具 6 > 防禦 5 > 技能 prio）→ 速度 → 回合內的固定亂數順序值 → 單位 id」排出穩定順序。
- ACTION_PREPARE：確認能否行動（睡眠、麻痺、退縮、破防、凍結、蓄力中）、重新確認目標（原目標倒下時改打同陣營的下一個）、驗證並支付成本（成本支付本身會產生事件）。
- ACTION_EXECUTION：建立 skill_cast_id，每段命中都有自己的 hit_id，逐段做「命中 → 效果 → 觸發 → 失去戰鬥能力判定」。
- 反應（反擊、殘影、荊棘、連擊）是正式的反應行動，有自己的 action_id，深度上限 2。
- 勝敗只在 VICTORY_CHECK 判定：一方全部失去戰鬥能力、逃跑成功、或被魔物逃走。

## D. 事件、觸發、效果

- 事件類型集中在 `EVT` 常數：戰鬥／回合／行動開始與結束、技能選擇／使用／成功／失敗、成本支付、資源增減／耗盡／滿值、命中／未命中／會心、傷害計算前後、造成／受到傷害、治療前後、狀態施加前／成功／失敗、層數改變、狀態移除／到期、失去戰鬥能力前後、追加／反應行動、行動取消、目標改變、效果觸發／完成、訊息、階段改變。
- 每個事件都有 event_id、phase、來源、目標、direct／root 來源、parent／root event、action_id、cast_id、hit_id、chain_depth、sequence、priority、tags、payload、快照、resolved、cancelled。
- PRE 可以修改、取消或替換（例：殘影閃避、不屈撐住）；MAIN 正式執行；POST 只能觸發與記錄，不能回頭改結果。
- 觸發條件：事件類型、階段、必須／排除的標籤、來源／目標條件、數值條件、資源條件、狀態條件、次數限制（每行動、每回合、每場）、機率、priority。
- 效果類型（通用語言）：damage、heal、drain、resource、status_apply、status_remove、cleanse、dispel、stage、shield、steal_gold、counter（反應行動）、extra_action、cancel_action、summon、phase、message、break_chip。技能、被動、狀態、敵人機制都只能用這些效果。
- 傷害管線的固定順序：基礎值 → 攻擊方修正 → 防禦方修正 → 技能修正 → 天賦修正 → 裝備修正 → 狀態修正 → 環境（天氣）→ 最終（護盾、防禦、格擋、下限 1）。修正器資料都標明所屬階段。
- 快照：觸發當下的數值快照（例：反彈傷害用「受到的傷害」）存在 TriggeredEffect，執行時讀快照；數值成長類效果讀即時值。每個效果在資料裡寫明。

## F. 狀態

- 主要異常（互斥群組 major）：中毒、灼傷、麻痺、睡眠，各有免疫、持續時間、回合結束傷害或行動前判定。
- 其他：潮濕、纏繞、護盾、防禦中、退縮、蓄力、空中（跳躍）、破防、凍結（時停）、煙幕、必定會心、附魔、反射鏡面、狂怒、能力等級（物攻／物防／魔攻／魔防／速度，正負層數 ±3，各自計時）。
- 每個狀態都寫明 duration_rule（在誰的哪個時間點遞減）、stack_rule、max、refresh_rule、remove 與 dispel 條件、免疫規則。

## G. 新玩法（規格第 10、11、16 節與多敵人）

1. **多敵人**：野外遭遇可能出現 1～3 隻。數量越多，每隻 HP 與攻擊越低（2 隻 HP×0.75／攻×0.85，3 隻 HP×0.6／攻×0.75），獎勵各自計算。精英與頭目原則上單挑，劇情頭目可召喚手下（盜賊頭目的手下改成真的單位）。
2. **目標規則**：單體、全體敵人、隨機、自己、全體我方。原本屬於範圍類的招式（落雷、炎浪、隕火、激流、天罰、翠葉風暴、蒸汽噴射、爆燃）改為全體攻擊，對多個目標時威力 ×0.75；連鎖雷主目標 100%、其他 50%。
3. **技能庫與技能槽**：主動技能槽 4 格＋職業招式固定 1 格。鑲在武器上的寶珠提供技能，使用 8 次就永久學會，卸下寶珠也不會消失。技能進化改記在技能庫上。技能槽在選單→技能編排。
4. **行動順序**：保留優先度（先制技能、防禦、道具、逃跑），新增延後與追加行動的效果類型。
5. **平衡原則**：不自動改數值，只輸出報告（純上位警告、使用率、Build 集中度、異常協同）。

## H. 自動測試（tools/btest.js，無畫面執行）

- 資料驗證：id 唯一、引用存在、必要欄位、標籤合法、數值範圍、上下限、觸發事件合法、效果存在、層數、資源上限、循環引用。
- 技能單元測試：合法／非法目標、成本足夠／不足、命中／未命中、會心、狀態成功／失敗、多目標、多段、施放者或目標中途倒下。
- 事件鏈：parent／root、depth、priority 穩定排序、PRE 取消、不會重複 MAIN、佇列清空。
- 無限循環：人工製造 A→B→A、反擊觸發反擊、資源增加觸發資源增加，確認在上限停下並留下事件鏈。
- 確定性：同種子、同輸入，事件序列雜湊值相同。
- Build 模擬：10 職業 × 技能組合 × 多組敵人（單體、多體、高防、高速、異常抗性、頭目），輸出總傷害、每回合傷害、承受傷害、治療、資源、技能使用率、勝率、平均回合、事件數。報告存成 docs/balance_report.md。
